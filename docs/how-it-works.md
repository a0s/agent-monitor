# Project agent-tree monitor

`link.sh` installs `.bin/agent-tree` and project-level Codex and Claude Code hooks in every existing worktree. A shared Git `post-checkout` hook installs them in future worktrees after checkout. This requires Git 2.54 or newer. With `git worktree add --no-checkout`, installation waits until that worktree is checked out; if it is never checked out, run `link.sh` again.

Run `.bin/agent-tree` from any worktree for a live terminal view. `--codex` and `--claude-code` filter by CLI, while `--json` prints one uncolored, machine-readable snapshot. Interactive output redraws every two seconds and uses a green `●` for running agents, a dim gray `○` for stopped agents, and a dim gray `?` when an agent's state is unknown. A dim `parent unknown` annotation means that the immediate parent was not supplied by the runtime.

The monitor reads events from the repository's shared Git directory, recent local transcripts, and Claude Code team configuration, then matches event-backed sessions to local processes. Event-backed nodes retain scalar `model` and `effort` slugs in JSON and show them as one `model/effort` pair in the terminal view. When Claude provides a background task description or a team member name, the monitor retains it as `title` and renders it after the pair. Missing hook values are recovered from an event transcript or agent transcript when possible, then explicitly shown as `unknown`; the monitor never guesses them from a process. Claude model slugs omit the `claude-` prefix, and Claude effort objects use their `level`. Claude Code transcript recovery reads assistant `message.model`, top-level effort, and an adjacent `.meta.json` file when available. A Claude subagent without `parent_agent_id` is nested below its `session_id` parent.

A `process only; runtime metadata unavailable` annotation marks sessions discovered only from a local process. Claude `bg-spare` helper processes do not create monitor nodes; a remaining Claude process is associated with the newest eligible session in its worktree. A matching process confirms that an event-backed session is running; without one, its state remains unknown even after a start event. Stop hooks remove a node from the live view unless it remains necessary as an ancestor of a live child. Processless unknown nodes are retained for fifteen minutes.

Codex may require trusting project hooks through `/hooks`. Until they are trusted, Codex events may be absent. Sessions started before installation are visible only when their process can be associated with a worktree. The monitor does not change global user settings.
